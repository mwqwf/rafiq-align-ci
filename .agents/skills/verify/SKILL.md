# التحقق قبل الإعلان (دليل أنثروبيك «How the Claude Code team thinks about verification» — 2026-11-16)

> «أُنجز» بلا فحصٍ شغّلتَه ودليلٍ أمامك ليست إنجازاً. الدستور في `workstyle`؛ هذه المهارة تضيف **الأوامر الفعلية هنا**.
> الأرخص أولاً، وإن سقط رخيصٌ فلا حاجة للثقيل. هذا مستودعٌ عامّ دقائقه مجّانية لكن الدلو حقيقةٌ مشتركة: لا كتابة فيه بلا حارس.

## ١. سلّم الفحص

| النوع | رخيص (ثوانٍ) | أثقل | الأثقل |
|---|---|---|---|
| أداة بايثون (`tools/**`) | `python3 -m py_compile <الملف>` · `python3 -m unittest tools.<حزمة>.test_<اسم> -v` (أو `python3 -m pytest -q <الملف>` حيث ذُكر في رأسه) | كل اختبارات الحزمة: `python3 -m unittest discover -s tools/index_qa -p 'test_*.py'` | — |
| حرّاس promote وdrop | `python3 -m unittest tools.index_qa.test_drop_ayahs tools.index_qa.test_promote_shrink tools.index_qa.test_approved_drop_guards` | `python3 -m unittest discover -s tools/ci_fleet -p 'test_*.py'` | — |
| workflows | `python3 -m unittest tools.ci_fleet.test_workflow_yaml_contract` · `python3 -m unittest discover -s tools/ci_fleet -p 'test_*contract.py'` | مراجعة `on:` و`concurrency` | تشغيلٌ حيّ بعد قراءة الأثر |
| فهرس أو بصمة جديدة في المسرح | `python3 tools/index_qa/run.py --struct-only <المفتاح>` (**مجاني وأول الأشياء**) | `openers.yml` | **أربعة ملوح** `audio_qa.yml` بـ`seed_salt` متمايزة ثم `promote.py --only <المفتاح>` |
| محاذاة CTC | `python3 -m unittest tools/alignment_v3/test_<…>.py` | `ctc_align.yml` بـ`probe_surahs` بلا رفع | `ctc_splice.yml` |

⛔ **لا تُطلق ملحاً قبل الفحص البنيوي**: أربع تشغيلاتٍ تضيع على فهرسٍ يردّه الحارس مجّاناً.

## ٢. اختباراتٌ تُفضَّل لأدوات المحاذاة
بعد أي سيناريو حقيقي: **property tests** (مكتبة Hypothesis إن كانت مثبَّتة في الجلسة — غير مثبَّتة افتراضياً هنا، فلا تضف تبعيةً للـCI بلا سبب؛ وإلا فاختبارٌ بمولّد عشوائيّ مثبَّت البذرة بـ`unittest`): خصائص مثل «المداخل مرتّبةٌ غير متداخلة» و«مجموع المدد ≤ طول الملف» و«الحجب لا يغيّر مداخل الآيات الباقية». و**differential** عند أي إعادة كتابة (المحاذاة القديمة والجديدة بالمدخلات نفسها وعدّ الفروق).

## ٣. الأثر لا الإطلاق
⛔ **لا إعلان نجاحٍ قبل قراءة الأثر من الدلو** (`timings/` و`state/`) أو `ops/out/*.txt`. «أُطلق» ليست «تمّ»، و`conclusion=failure` في اللوحة ليس حكماً. وللقياس الحيّ استعمل أوامر `ops/commands/` (`state` و`tool` و`dispatch`) وفق `CLAUDE.md`. وما لم يُشغَّل يُذكر بسببه ولا يُدّعى.

## ٤. الدليل المطلوب في التقرير
لكل فحصٍ: **الأمر حرفياً + سطر المخرج الدالّ** (مثل `Ran 47 tests … OK`) أو مسار الأثر في الدلو. لا «تم التحقق» بلا أمر.

## ٥. قواعد لا تُكسر
1. **التغيير لا يعدّل الفحص الذي يحكم عليه.** ممنوعٌ تعديل حارسٍ أو اختبارٍ لجعله يمرّ؛ وأي تعديلٍ عليه يجعله **أصعب خداعاً لا أضعف** ويُختبر نصّاً قبل استعماله. **لا تحريف لنص القرآن · لا تُخفَّض عتبة العطب الجسيم 5% · لا يُعطَّل حارس · والحدّ الحدّيّ يُحسم بعيّنةٍ أكبر (أربعة ملوح أخرى) لا بعتبةٍ أصغر.** قواعد المراجعة تُقرأ من `origin/main`: `git show origin/main:REVIEW.md`.
2. **الاختبار المتقلّب** لا يُتخطّى ولا يُضاف له `retry`/`sleep`: يُصلَح سببه أو يُحذف بسببٍ مكتوب.
3. **ثلاث جولات** إصلاحٍ فاشلةٍ لفحصٍ واحد ⇒ توقّف عن الترقيع؛ اكتب العائق بنصّ خطئه في `ops/out/BLOCKED.md` وامضِ إلى بندٍ آخر (لا يتوقف العمل كلّه).
4. **خطأٌ فائتٌ تكرّر** في طلبين فأكثر ⇒ يُضاف قاعدةً في `REVIEW.md` أو حارساً، وتُنظَّف القوائم دورياً.

## ٦. مراجعةٌ مستقلة قبل الإيداع (لتغييرٍ غير بسيط)
الوكيل `reviewer` (`.claude/agents/reviewer.md`) أو `/code-review` ثم `/simplify`؛ و`/security-review` عند مسّ أمرٍ أمني. الجولة ≤ ٣.

## ٧. الإيداع
`git add <مسارات>` ثم `git commit -m … -- <المسارات>` (لا `-A` ولا `-a` ولا rebase). وقبل الدفع افحص `on:`: هل مساراتك تطلق تشغيلةً (مجانيةٌ هنا لكن تُسمَّى). وسمٌ قبل سطري الإسناد:
```
Verified: unittest tools.index_qa.test_drop_ayahs + run.py --struct-only <مفتاح>
Verified: none (توثيق فقط)
```
